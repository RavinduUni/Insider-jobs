# InsiderJobs — System User Manual

This manual explains how to use the InsiderJobs platform from the perspective of each of the three user roles: **Student**, **Recruiter** (referred to as "Project Owner" in the UI), and **Admin**. It follows the actual screens, buttons, and labels present in the application.

---

## 0. Getting Started — Choosing a Portal

InsiderJobs has three separate entry points:

| Portal | URL | Who uses it |
|---|---|---|
| Public site | `/` | Anyone — browse projects, companies, pricing, about |
| Student / Recruiter Auth | `/auth?type=student` or `/auth?type=recruiter` | Students and Recruiters register/login here |
| Admin Login | `/admin-login` | Platform administrators only |

On the public homepage, use the **"Are you a recruiter? / Are you a student?"** link at the bottom of the auth form to switch portals, or the top navigation to jump straight to a specific login/register mode.

## 1. Student Manual

### 1.1 Creating a Student Account

1. Go to `/auth?type=student&mode=register` (the **Student Portal** register form).
2. Fill in **Full Name**, **University**, **Degree / Major**, **Email**, and **Password**.
   - Password must be at least 8 characters, contain one uppercase letter and one number (a strength meter — Weak/Medium/Strong — appears as you type).
3. Optionally upload your **Resume** (.pdf or .docx, max ~5–10MB) in the upload box.
4. Click **Send OTP** — a 6-digit one-time code is emailed to the address you entered (via the platform's email service).
5. Enter the code in the **Enter OTP** field that appears, then click **Verify OTP & Create Account**.
6. On success you are automatically logged in and redirected to `/student-dashboard`.

> If the OTP does not match, registration fails and you're returned to the homepage — request a new OTP by resubmitting the form.

### 1.2 Logging In

Go to `/auth?type=student&mode=login`, enter your email and password, and click **Login**. A JWT session token is stored in your browser; you'll be redirected to your Student Dashboard. Your session auto-expires when the token's expiry time is reached (you'll be logged out automatically and redirected to login).

### 1.3 Student Dashboard Overview

The left sidebar gives access to every student feature:

| Menu Item | Purpose |
|---|---|
| **Dashboard** | Overview: project/application/NDA status charts, active projects, recent applications, earnings snapshot, AI-recommended projects |
| **Browse Projects** | Search & filter all open projects |
| **Applied Projects** | Track the status of every application you've submitted |
| **NDA Requests** | Review, download, and upload signed NDAs |
| **Submissions** | (Placeholder page for submitted deliverables) |
| **Resume Builder** | Build and export a resume, with AI-assisted writing |
| **Wallet** | View earnings, pending balance, and transaction history |
| **Settings** | Edit profile, notifications, and change password |

The **Dashboard** home page also shows an **AI-recommended projects** panel ("Recommended for You") — this is generated by asking Google Gemini to match your bio/skills against currently open projects and score them; it refreshes automatically once per session.

### 1.4 Browsing and Filtering Projects

On **Browse Projects**, you can:
- Search by title, category, technology, or recruiter name in the top search bar.
- Sort by Newest, Oldest, Highest Budget, or Lowest Budget.
- Filter using the left sidebar: **Category**, **Budget Range**, **Deadline** (e.g. "Due today," "Under 1 week"), and **Required Skills** (multi-select checkboxes).
- Click **Clear all** to reset every active filter.
- Click any project card to open its full detail page (`/apply-project/:id`).

### 1.5 Applying for a Project

From a project's detail page, click **Apply for this Project**. If you aren't logged in, you'll be prompted to log in first. Applying is a 3-step modal:

1. **Upload CV** — upload your CV/résumé (.pdf or .docx, max 5MB).
2. **Project Plan** — upload a project plan/proposal document, plus optional **Additional Notes** describing your approach or timeline.
3. **Submit** — review and click **Submit Application**.

Behind the scenes, your CV and plan are uploaded to secure cloud file storage and an `Application` record is created with status **"applied"**. You'll see a confirmation animation once the submission succeeds.

### 1.6 Tracking Applications

On **Applied Projects**, filter by status using the tab row at the top. Status meanings:

| Status | Meaning |
|---|---|
| Under Review (`applied`) | Submitted, awaiting recruiter decision |
| Selected (`selected`) | Recruiter has shortlisted you — an NDA will typically follow |
| NDA Sent / NDA Accepted | An NDA has been sent to you / you have accepted it |
| Assigned (`assigned`) | You have been formally awarded the project |
| In Progress | The project is now underway |
| Completed | The project has been marked as finished |
| Rejected | Your application was not selected |

Click **View Details** on any application card to see full project info in a modal, or **Review NDA** to jump straight to the NDA screen.

### 1.7 Managing NDAs

On **NDA Requests**:
- **Pending NDA Requests** lists NDAs sent to you awaiting action.
- Click **View NDA** to open the agreement text plus:
  - **Download Received NDA** — downloads the document the recruiter sent.
  - **Choose Signed NDA File** — select your signed copy (.pdf/.doc/.docx) from disk.
  - **Upload Signed NDA** — submits your signed file back to the recruiter, which updates the record for their review.
- **NDA History** shows previously accepted/rejected NDAs — click **View** to re-open any of them.

### 1.8 Resume Builder

An in-browser resume editor at **Resume Builder**:
- Fill in **Personal Information**, add multiple **Work Experience** and **Education** entries, and add **Skills** (press Enter to add a chip).
- Click **Enhance with AI** next to the Professional Summary or any experience description to have Google Gemini rewrite that text for clarity/impact — the improved text replaces the field automatically.
- A live preview renders on the right as you type.
- Click **Download .docx** (top-right or in the preview header) to export a formatted Word document of your resume.

> Note: this tool is independent from the "Resume" file you upload in Settings/registration — it produces a downloadable file only, it does not save to your profile automatically.

### 1.9 Wallet

The **Wallet** page shows:
- **Total Earned**, **This Month**, and **Pending** (funds in escrow) stat cards.
- An area chart of earnings over the last 7 months.
- Full **Transaction History** (credits/debits with dates, descriptions, and status).
- A **Withdraw Funds** button (UI present; connect to your preferred payout method as configured by the platform).

Transactions populate once a recruiter marks one of your projects as paid (see §2.9 below).

### 1.10 Settings

Four tabs:
- **Profile** — edit name, phone, university, major, graduation year, bio, skills, portfolio/LinkedIn/GitHub links, upload a new profile photo, and upload/replace your resume. Click **Edit Profile**, make changes, then **Save Changes**.
- **Account** — placeholder ("coming soon").
- **Notifications** — toggle email/push notification preferences per category (New Projects, Applications, Payments, NDA Requests). Click **Edit Notifications** → toggle → **Save Changes**.
- **Security** — **Change Password**: enter and confirm a new password, click **Change Password** to trigger an OTP email, enter the received 6-digit code, then **Confirm New Password**.

## 2. Recruiter (Project Owner) Manual

### 2.1 Creating a Recruiter Account

1. Go to `/auth?type=recruiter&mode=register`.
2. Fill in **Full Name**, **Company Name**, **Email**, **Password**, and optionally upload a **Company Logo** (.png/.jpg/.jpeg).
3. Click **Verify OTP & Create Account** — unlike students, recruiter registration does **not** require an OTP step; account creation is immediate.
4. You're logged in automatically and redirected to `/owner-dashboard`.

### 2.2 Logging In

`/auth?type=recruiter&mode=login` — enter email/password and click **Login**.

### 2.3 Owner Dashboard Navigation

Left sidebar:

| Menu Item | Purpose |
|---|---|
| **Dashboard** | Landing/overview page |
| **My Projects** | Manage all projects you've posted |
| **Create Project** | Post a new project |
| **All Applicants** | See applicants across every project you own |
| **NDA Management** | Track NDA agreements sent to students |
| **Payments** | Pay students for completed projects, view payment history |
| **Settings** | Company profile, security |

### 2.4 Creating / Editing a Project

From **Create Project**, fill out:
- **Project Details**: Title, Category (dropdown), Description, Budget (USD), Deadline (must be a future date).
- **Technologies**: type comma-separated values or click suggested technology chips (React, Node.js, Python, etc.).
- **Project Requirements**: add one at a time (type + Enter or click **+**).
- **Deliverables**: add one at a time, same pattern.
- A live **Project Preview** card summarizes everything before submission.
- Click **Post Project** to create it, or **Update Project** if you arrived via the **Edit** button on an existing project (`/owner-dashboard/create-project/:projectId`).

All fields are validated client-side (valid budget number, future deadline, at least one requirement/deliverable, at least one technology).

### 2.5 Managing Projects

On **My Projects**, filter by status (**Open**, **Has Applicants**, **In Progress**, **Submitted**, **Completed**). Each project card shows budget, applicant count, deadline, and posting date, with action buttons:
- **View** — opens the public project detail page.
- **Applicants (N)** — jumps to that project's applicant list.
- **Edit** — reopens the Create/Edit Project form pre-filled.
- **Review Work** — appears once status is `submitted`, links to the submission review screen.
- **Delete** — opens a confirmation modal warning that the project and all its applications will be permanently deleted, then removes it via the delete-project API (cascades to applications on the server).

### 2.6 Reviewing Applicants

Two views cover the same data:
- **All Applicants** — grouped by project, shows the first 4 applicants per project with a **View All →** link to see the rest.
- **All Applicants → (per-project)** — the full grid of applicants for one specific project.

Each applicant card shows their name, university/major, skills, notes/bio, and how long ago they applied, plus action buttons:
- **View** — opens the full **Student Details** page (see §2.7).
- **Send NDA** — opens a modal to upload an NDA document (.pdf/.doc/.docx) and send it to that applicant; this is disabled once an NDA is already sent or accepted (button shows "NDA Sent" / "Signed" instead).
- **Assign** — enabled only once the applicant's status is `selected` (i.e., after NDA acceptance workflow); opens the **Assign Project** modal.

### 2.7 Viewing a Student's Full Profile

From any applicant list, **View** opens `/owner-dashboard/view-details?studentId=...&projectId=...`, showing:
- Profile header: photo, name, university, degree, location, contact info, and current application status badge.
- Stat cards: Projects Completed, Member Since, Applied date, and (if available) their average Rating.
- **View NDA** button — enabled once the NDA is accepted; opens the NDA text plus a **Download Signed NDA** action.
- **Assign Project** button — enabled once NDA is accepted and the applicant isn't already assigned; opens the confirmation modal.
- **About**, **Skills & Expertise**, and a **Client Feedbacks** carousel of past reviews from other recruiters (drag to scroll).
- **Documents** panel — direct links to the applicant's CV/Resume and Project Plan.
- **Links** panel — Portfolio, LinkedIn, GitHub (only shown if provided).
- **Earnings** panel — total earnings and response rate, if the student has completed prior projects.

### 2.8 Assigning a Project

Clicking **Assign Project** / **Confirm Assignment** calls the assign-project endpoint, which:
1. Marks that student's application as **assigned**.
2. Updates the project's status to **in progress**.
3. Automatically marks every other applicant on the same project as **rejected**.

This action is irreversible from the UI — a warning banner in the modal states that other applicants will be automatically rejected once you confirm.

### 2.9 NDA Management (Owner View)

The **NDA Management** page gives a platform-wide view of all NDAs you've sent, with stat cards (Total, Pending, Accepted, Rejected) and status filter tabs. For each NDA you can:
- **View NDA** — open the agreement text and sent/accepted dates in a modal.
- **View Applicant** — jump to that student's detail page.
- **Download** — download the signed document once accepted.

### 2.10 Payments

On **Payments**:
- Summary cards show **Total Paid Out**, **Pending Payments**, **Projects Completed**, and **Awaiting Payment** counts.
- Filter completed projects by **All / Awaiting Payment / Paid**.
- For an unpaid completed project, click **Pay Now · $amount** to open the payment modal:
  1. **Payment** step — enter cardholder name, card number, expiry, CVV (this is a simulated/demo payment form; no external payment gateway is wired in — submitting calls the platform's own `process-payment` endpoint, which records the transaction and marks the project paid).
  2. **Review** step — after "payment" succeeds, rate the student 1–5 stars and optionally leave a comment, then **Submit Review** (or **Skip Review**).
  3. **Done** — confirmation screen.
- A **Transaction History** table lists every completed payment.

### 2.11 Settings (Owner)

- **Profile** tab — company logo, company name, contact person, email, phone, industry, company size, location, "Hiring For" tags, bio, and social/website links. Edit → Save Changes.
- **Account** — placeholder.
- **Notifications** — placeholder ("coming soon").
- **Security** — same OTP-based change-password flow as students (**Change Password** → OTP emailed → enter code → **Confirm New Password**).

## 3. Admin Manual

### 3.1 Logging In

Admins do not share the student/recruiter auth page. Go to `/admin-login`:
- Toggle between **Sign In** and **Register** (Create Account) using the link at the bottom.
- Register requires Full Name, Email, Password; Login requires Email, Password only.
- On success you're redirected to `/admin-dashboard`.

> Note: unlike student/recruiter registration, admin account creation currently has no invitation/approval gate in the UI — treat the admin registration link as something to be shared only with trusted platform operators.

### 3.2 Dashboard Navigation

Left sidebar sections:

| Section | Contents |
|---|---|
| **Overview** | Platform-wide analytics |
| **Students** | Manage all student accounts |
| **Recruiters** | Manage all recruiter/company accounts |
| **Projects** | Manage all posted projects |
| **Applications** | Read-only list of every application on the platform |
| **NDAs** | Read-only list of every NDA on the platform |

Use **Log Out** at the bottom of the sidebar to end your session.

### 3.3 Overview Analytics

The Overview tab shows:
- A **Platform Entities** bar chart (counts of Students, Recruiters, Projects, Applications, NDAs).
- A **User Distribution** donut chart (Students vs. Recruiters).
- **Recent Projects** — the newest posted projects with their status.
- **Newest Students** — the most recently registered students.

### 3.4 Managing Students / Recruiters / Projects

Each of these tabs shows a searchable, sortable table:
- Use the **Search** box to filter by name, email, title, or company name.
- Click the **chevron (→)** icon on a row to open a **Details** view showing every field on that record (excluding password/internal IDs).
- Click the **trash icon** to open a confirmation modal ("You are about to permanently delete: '[name]' — This action cannot be undone"), then **Delete** to confirm.

Deleting a **Student** cascades on the server: their profile picture, resume, and every application's CV/plan files are removed from cloud storage, along with all their `Application`, `Review`, and associated `NDA` records, before the student document itself is deleted.

Deleting a **Recruiter** or **Project** similarly removes dependent records server-side.

### 3.5 Viewing Applications and NDAs

The **Applications** and **NDAs** tabs are read-only lists (no edit/delete actions in the current UI) — useful for platform-wide auditing of who applied where and which NDAs are outstanding.

## 4. Cross-Role Reference

### 4.1 Application Status Glossary

| Status | Set by | Meaning |
|---|---|---|
| `applied` | Student applies | Awaiting recruiter review |
| `selected` | Recruiter | Shortlisted, NDA workflow begins |
| `rejected` | Recruiter (manual or automatic) | Not chosen; automatic on other applicants once one is assigned |
| `assigned` | Recruiter (Assign Project) | Formally awarded the project |

### 4.2 NDA Status Glossary

| Status | Meaning |
|---|---|
| `nda_sent` | Recruiter has sent the NDA document; awaiting the student |
| `accepted` | Student uploaded a signed copy |
| `rejected` | Student/recruiter marked it rejected |

### 4.3 Project Status Glossary

| Status | Meaning |
|---|---|
| `open` | Accepting applications |
| `has applicants` | At least one application received |
| `in progress` | A student has been assigned and is working |
| `completed` | Marked finished (payment can be processed) |

## 5. Known Limitations (Current Build)

For transparency, a few areas of the current implementation are worth knowing about before relying on them operationally:

- **Payments are simulated** — the card form on the recruiter Payments page does not integrate a real payment gateway (e.g. Stripe/PayPal); it demonstrates the UX and records the transaction directly via the platform's own API.
- **Student "Submissions" page and recruiter "Review Submission" screen** currently show placeholder/sample content rather than live submitted-file data — a full deliverable-submission workflow is not yet wired end-to-end.
- **Notification toggles** (Settings → Notifications, both roles) are UI-only in the current build and are not yet connected to an actual email/push delivery preference on the server.
- **Admin API routes** (`/api/admin/*`) do not currently require a login token on the server side — access to `/admin-login` is the only UI-level gate. Treat admin credentials with the same care as full database access.
- **OTP codes** are returned directly in the API response consumed by the frontend (rather than only being verified server-side), so treat OTP emails as a convenience check rather than a strict security boundary.
